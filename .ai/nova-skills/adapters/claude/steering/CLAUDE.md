# NOVA Workspace — Claude Adapter

This file is generated by NOVA's adapters procedure (`.ai/nova-skills/adapters/SKILL.md`) and lives at `.claude/CLAUDE.md` — gitignored, per-developer, regenerable. It is **not** a replacement for `AGENTS.md`; the `@` imports above load the framework defaults and your workspace overrides into context at session start.

## Why this file exists

Claude Code reads `CLAUDE.md` natively but does **not** read `AGENTS.md` unless explicitly imported. This adapter chains two `@` imports above so Claude Code expands them transitively into context at launch:

1. `AGENTS.md` — framework defaults (identity, safety, navigation entry point).
2. `.ai/workspace/AGENTS.md` — workspace identity and overrides. If absent, onboarding hasn't run — the agent should fall back to the framework defaults and flag it.

The repository map (`.ai/workspace/map/repos.md`) and personal-knowledge-management doctrine were previously auto-loaded too. They were dropped on 2026-04-30 to reduce always-on token weight — the agent reads them on demand when the task actually needs them.

## Anti-duplication rule (strict)

Every rule NOVA enforces — safety, navigation, identity, skills, workspace overrides — lives under `AGENTS.md` or `.ai/`. This adapter is a **pointer**, not a copy.

- **Reference, never reproduce.** Do not paraphrase safety or navigation rules into chat responses, generated code comments, or new files. Reference the source path (`AGENTS.md:<line>`, `.ai/workspace/AGENTS.md:<line>`).
- **Do not add Claude-specific rules to this file.** If a rule is Claude-specific enough to warrant strict behavior, put it at `.ai/nova-skills/adapters/claude/<rule>.md` and reference it here with an `@` import — same pattern Kiro uses for `.ai/nova-skills/adapters/kiro/terminal.md`.
- **If a rule applies to all agents, it belongs in `AGENTS.md` or `.ai/`**, not here. This adapter does not own any rule.

## What to read, in order

The `@` imports at the top auto-load `AGENTS.md` + `.ai/workspace/AGENTS.md`. Everything else is on-demand:

- Per-repo `AGENTS.md` — when working in a specific repo under `git-repositories/`. NOVA does NOT drop subdir `CLAUDE.md` shims into cloned repos (the adapter refuses to write under `git-repositories/<repo>/`). For repo-bounded tasks, prefer the `repo-worker` subagent.
- Repo map (`.ai/workspace/map/repos.md`), skills, learnings, procedures — read when the task demands them, not preemptively.

## Enforcement layer

This adapter implements the `.ai/enforcement.md` contract:

- **C1 — Session-start broadcast** via the `@` imports above (`AGENTS.md` + `.ai/workspace/AGENTS.md`).
- **C3 — Scoped rule activation** is **not implemented in the main agent** on Claude. Auto-load inside a cloned repo would require writing into someone else's git tree, which the adapter procedure refuses. C3 is delegated to **S2 — `repo-worker` subagent**: caller names the target repo at invocation, the subagent's system prompt reads that repo's `AGENTS.md` as its first action.
- **C4 — User-skill surfacing** via `SessionStart` + `UserPromptSubmit` hooks that mirror `.ai/workspace/skills/` → `.claude/skills/` (the latter for mid-session refresh).
- **C2 was removed 2026-04-30.** See `.ai/enforcement.md` § "Removed capabilities".

See `.ai/nova-skills/adapters/claude/README.md` for the capability mapping table.
