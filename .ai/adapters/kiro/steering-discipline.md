# Kiro — Steering Discipline (Strict, Non-Negotiable)

Referenced from `.kiro/steering/nova.md`. Kiro auto-injects every `inclusion: always` steering file into every chat. That's powerful and dangerous — context budget is finite, and content inlined here is paid for on every turn forever.

These rules exist because Kiro steering tends to grow fat over time: "small additions" pile up, learnings get pasted in, AGENTS.md content gets duplicated for "convenience." That's the failure mode. Obey these to prevent it.

## Rules

### 1. Steering files are pointers, never caches.
Never paste content from `AGENTS.md`, `.ai/workspace/`, `.ai/<skill>/`, or `learnings/` into a steering file. If steering needs to surface that content, use `#[[file:<workspace-relative-path>]]` — Kiro inlines by reference, not by copy, so the source stays the single source of truth.

### 2. Use `#[[file:]]` live refs, not paraphrased prose.
If you find yourself summarizing a `.ai/` file's content inside a steering file, stop. Either ref the file directly or trust the agent to read it on demand via the Navigation Protocol.

### 3. Don't preload learnings.
`.ai/workspace/learnings/` exists for *on-demand* loading via Navigation Protocol step 7. Never add `inclusion: fileMatch` globs or `#[[file:]]` refs that pull learnings into always-on context. Learnings are scanned when relevant — that's their whole point.

### 4. Don't add new `inclusion: always` files casually.
Each `inclusion: always` file is paid for on every Kiro turn forever. The bar for adding one: the content is genuinely platform-specific (Kiro-only) AND must be present from cold. If either test fails, the rule belongs in `AGENTS.md` or `.ai/`, loaded on demand.

### 5. Push back when asked to "make X always available."
"Always available" almost never means "must auto-inject into every chat." It usually means "the agent should know to look there." That's what the Navigation Protocol covers. Auto-injection is the wrong tool for "discoverability."

### 6. ~50-line steering files are a smell.
A healthy steering file in this adapter is short — `nova.md` itself is ~25 lines, mostly `#[[file:]]` refs. If a steering file grows past ~50 lines, investigate before adding more. The fix is usually to extract content into `.ai/` and replace inlined text with a ref.

### 7. Don't hand-edit `.kiro/steering/` files generated by `nova-adapters`.
`.kiro/` is regenerable runtime output. Per-repo steering files (`.kiro/steering/<repo-slug>.md`) are produced by the adapter procedure from `.ai/adapters/kiro/templates/repo-steering.md`. Editing them in place is wasted work — the next `nova-adapters` run overwrites. Any improvement belongs in the source template at `.ai/adapters/kiro/`.

### 8. If you must add content to steering, justify it explicitly.
Tell the user: which rule above does this exception relate to, and why this content cannot live in `.ai/` and be referenced. If you can't justify it, don't add it.
