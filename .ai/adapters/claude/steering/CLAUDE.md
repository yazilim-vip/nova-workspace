# NOVA Workspace — Claude Adapter

This file is generated by NOVA's adapters procedure (`.ai/adapters/README.md`) and lives at `.claude/CLAUDE.md` — gitignored, per-developer, regenerable. It is **not** a replacement for `AGENTS.md`; the `@` imports above load the framework's real instructions into your context at session start.

## Why this file exists

Claude Code reads `CLAUDE.md` natively but does **not** read `AGENTS.md` unless explicitly imported. The repository's committed root `CLAUDE.md` currently uses a plain text instruction ("Always read AGENTS.md") — that's context, not enforcement. This adapter strengthens the guarantee with three chained `@` imports above, which Claude Code expands transitively into context at launch.

The chain loads steps 1–3 of the Navigation Protocol automatically:

1. `AGENTS.md` — framework defaults.
2. `.ai/workspace/AGENTS.md` — workspace identity and overrides. If absent, onboarding hasn't run — the agent should fall back to the framework defaults and flag it.
3. `.ai/workspace/map/repos.md` — repository map. Loaded so `git-repositories/` paths are never guessed.

Steps 4+ (per-repo `AGENTS.md`, skills, learnings) remain on-demand per the Navigation Protocol.

## Anti-duplication rule (strict)

Every rule NOVA enforces — safety, navigation, identity, skills, workspace overrides — lives under `AGENTS.md` or `.ai/`. This adapter is a **pointer**, not a copy.

- **Reference, never reproduce.** Do not paraphrase safety or navigation rules into chat responses, generated code comments, or new files. Reference the source path (`AGENTS.md:<line>`, `.ai/workspace/AGENTS.md:<line>`).
- **Do not add Claude-specific rules to this file.** If a rule is Claude-specific enough to warrant strict behavior, put it at `.ai/adapters/claude/<rule>.md` and reference it here with an `@` import — same pattern Kiro uses for `.ai/adapters/kiro/terminal.md`.
- **If a rule applies to all agents, it belongs in `AGENTS.md` or `.ai/`**, not here. This adapter does not own any rule.

## What to read, in order

The `@` imports at the top handle steps 1–3 automatically. The rest you load on demand per the Navigation Protocol in `AGENTS.md`:

1. `AGENTS.md` — framework defaults. **Auto-loaded via `@` import.**
2. `.ai/workspace/AGENTS.md` — workspace identity and overrides. **Auto-loaded via `@` import** (if present).
3. `.ai/workspace/map/repos.md` — repository map. **Auto-loaded via `@` import** (if present).
4. Per-repo `AGENTS.md` — when entering a specific repo under `git-repositories/`. **Read on demand**, per Navigation Protocol step 4. NOVA does NOT drop subdir `CLAUDE.md` shims into cloned repos (the adapter procedure refuses to write under `git-repositories/<repo>/`). For tasks bounded to one repo, prefer the `repo-worker` subagent — it pre-loads framework + workspace + repo-map and reads the named repo's `AGENTS.md` as its first action.
5. Skills, learnings, procedures — on demand per the Navigation Protocol.

Do not preload (beyond the chain above). Do not guess. Do not duplicate.

## Enforcement layer

This adapter implements the `.ai/enforcement.md` contract:

- **C1 — Session-start broadcast** via `SessionStart` hook that prints `.ai/adapters/_shared/checklist.md`.
- **C2 — Per-turn re-injection** via `UserPromptSubmit` hook that prints the same checklist.
- **C3 — Scoped rule activation** is **not implemented in the main agent** on Claude. Auto-load inside a cloned repo would require writing into someone else's git tree, which the adapter procedure refuses. C3 is delegated to **S2 — `repo-worker` subagent**: caller names the target repo at invocation, the subagent's system prompt reads that repo's `AGENTS.md` as its first action.

See `.ai/adapters/claude/README.md` for the capability mapping table.
